# ColoBot 普通用户版 — 产品规划文档

---

## 一、市场定位

### 1.1 空白地带

当前 AI 助手市场存在一个明显的断层：

| 层级 | 产品 | 特点 | 局限 |
|------|------|------|------|
| LLM 演示产品 | ChatGPT、Kimi、豆包 | 开箱即用，零门槛 | 无长期记忆，每次从头开始；无法定制；数据在云端 |
| Agent 框架 | LangChain、Dify、Coze | 可定制、可编排 | 需要编程或理解抽象概念；部署复杂 |
| **ColoBot 普通用户版** | **（当前空白）** | **有长期记忆、可定制行为、数据在本地，但不需要编程** | — |

ColoBot 普通用户版填补的正是这个空白：一个不需要编程、不需要部署、不需要理解 Agent 概念的 AI 助手，但它能记住你、关心你、并且你可以完全控制它。

### 1.2 目标用户画像

- 想拥有"越用越懂自己"的 AI 助手，但不会写代码的人
- 对隐私敏感，不想把聊天记录和个人数据放在云端的人
- 尝试过 LLM 演示产品，但觉得"每次都重新介绍自己很烦"的人
- 愿意花 5 分钟做初始设置，换取长期个性化体验的人

## 二、产品原则：三个"零"

### 2.1 零概念

用户界面上永远不出现以下词汇：

- Agent / Sub-Agent / Tool / Provider / API Key 归属
- SOP / 意图识别 / 上下文窗口 / Token
- 向量搜索 / 嵌入 / 记忆检索

取而代之的是用户能理解的语言：

| 技术术语 | 用户语言 |
|---------|---------|
| add_memory | "让 AI 记住这件事" |
| 启用主动干预 | "开启自动关心" |
| /context | "你的数据面板" |
| 系统提示词 | "AI 的行为设置" |

### 2.2 零配置

- 安装后首次启动，引导用户完成 **3 个选择**：选语言 → 填 API Key → 选 AI 关心你的程度
- 其余所有设置均有默认值，不需要用户改动
- 高级设置折叠在二级菜单，不影响首次体验
- API Key 本地加密存储，ColoBot 不经手

### 2.3 零部署

- 桌面应用形态（Electron / Tauri），下载即用
- 首次打开即进入引导流程，不需要接触终端
- 数据默认存储在本地 IndexedDB，用户感知不到数据库的存在
- 自动更新，静默升级

## 三、核心差异化

### 3.1 长期记忆：不是"上下文"，是"了解你"

**LLM 演示产品**：每次对话独立，AI 不记得你上次聊了什么。

**ColoBot 普通用户版**：

- AI 自动从对话中提取重要信息，存入记忆
- 下次对话时，AI 自动调取相关信息，不需要用户重复介绍自己
- 用户可以在"AI 知道的关于我的事"面板中查看、编辑、删除任何记忆

**用户感知**：

> "这个 AI 真的记得我说过的事，而且我不需要告诉它'请记住'。"

### 3.2 主动性：不是"等你问"，是"关心你"

**LLM 演示产品**：完全被动，等用户输入。

**ColoBot 普通用户版**：

- 默认开启轻度主动关心：每天第一次打开时，AI 根据今日待办、天气、情绪记录给出个性化问候
- 可选开启深度主动关心：检测到用户情绪持续低落时，建议联系朋友（需用户确认）
- 用户随时可关闭所有主动行为

**用户感知**：

> "它不是那种只会回答问题的机器人，它真的会关心我今天过得好不好。"

### 3.3 安全感：不是"承诺"，是"可验证"

**LLM 演示产品**：安全策略是黑盒，用户无法验证。

**ColoBot 普通用户版**：

- 用户可以在"安全日志"中看到 AI 拦截了什么输出（如果有）、为什么拦截
- 用户可以在"数据在哪"面板中确认：我的聊天记录存在本地、我的 API Key 加密存储、我的数据从未上传
- 用户随时可以导出全部数据，或者一键删除所有数据

**用户感知**：

> "我知道这个 AI 不会乱说话，我也知道我的数据在哪。不是因为它承诺了，是因为我能亲眼看到。"

### 3.4 定制性：不是"选角色"，是"调行为"

**LLM 演示产品**：只能选择预设的系统提示词（"你是一个幽默的助手"）。

**ColoBot 普通用户版**：

开关式行为定制：

| 开关 | 选项 |
|------|------|
| AI 说话风格 | 简洁 ↔ 详细 |
| AI 主动性 | 仅应答 ↔ 主动问候 ↔ 主动关心 |
| AI 记忆范围 | 仅本次对话 ↔ 记住重要信息 ↔ 记住一切 |
| AI 数据可见性 | 不读取个人数据 ↔ 读取情绪/习惯 ↔ 读取全部 |

每个开关都有简短的说明，帮助用户理解开启后的效果。

**用户感知**：

> "我不需要写 prompt，我只需要打开几个开关，AI 就变成了我想要的样子。"

## 四、技术方案

### 4.1 复用开发者版核心

ColoBot 普通用户版不是重新开发，而是在开发者版核心包之上，套一层用户界面壳。

| 开发者版 | 普通用户版 |
|---------|-----------|
| `@colobot/core` | 复用，通过前端调用 |
| `@colobot/sentinel` | 复用，安全策略由界面开关控制 |
| `@colobot/assistant` | 默认安装，模块通过开关启用 |
| `@colobot/sop-base` | 不暴露，后续可通过插件市场引入 |
| TUI | 替换为桌面 GUI |
| CLI 命令 | 替换为界面按钮 |

### 4.2 用户自带 API Key

- API Key 由用户自行获取（OpenAI / Anthropic / MiniMax 等）
- ColoBot 客户端加密存储 Key，只用于向 LLM 服务发送用户对话请求
- ColoBot 服务器不经手任何用户的对话内容——流量直连用户到 LLM 服务
- 用户可随时更换或删除 Key

### 4.3 端到端加密云同步

- 对话记忆、个人数据（待办、情绪、习惯等）在本地加密后同步到云
- 加密 Key 由用户掌握（派生自密码），ColoBot 服务端无法解密用户数据
- 多设备同步时，新设备需要输入密码才能解密数据
- 同步服务是 opt-in，默认仅本地存储

### 4.4 IndexedDB 本地存储

- 所有对话历史、个人数据默认存储在浏览器/桌面应用的 IndexedDB 中
- 用户无需安装数据库、不需要配置存储路径
- 数据在应用内可导出（JSON/CSV）、可删除

## 五、功能清单（按优先级）

### P0：核心体验闭环（首版必须）

| 功能 | 用户感知 |
|------|---------|
| 引导式初始设置 | 3 步走：语言 → API Key → 关心程度 |
| 基础对话 | 和 ChatGPT 一样流畅，但数据在本地 |
| 长期记忆 | AI 自动记住重要信息，可查看/编辑/删除 |
| 安全日志 | 用户可查看拦截记录和数据存储位置 |
| 行为开关 | 简洁 ↔ 详细 / 被动 ↔ 主动 / 记忆范围 |

### P1：差异化体验（次版）

| 功能 | 用户感知 |
|------|---------|
| 轻度主动问候 | 每日首次打开时个性化问候 |
| 情绪日记 | AI 自动追踪情绪趋势，展示图表 |
| 数据导出/删除 | 一键导出或清空所有数据 |
| 端到端加密同步 | 多设备同步，服务端无法解密 |

### P2：生态扩展（后续）

| 功能 | 用户感知 |
|------|---------|
| 插件市场 | 一键安装社区贡献的 SOP（如"帮我写论文"） |
| 深度主动关心 | 情绪低落后建议联系朋友（需确认） |
| Web 版 | 浏览器打开即用，无需安装 |

## 六、发布策略

| 阶段 | 目标 | 时间 |
|------|------|------|
| Alpha | 技术用户内测，验证核心体验闭环 | 开发者版 v0.4 之后 |
| Beta | 非技术用户测试，验证"三个零"是否成立 | Alpha 反馈后 2-4 周 |
| 1.0 | 正式发布桌面应用（Windows/macOS/Linux） | Beta 稳定后 |

---

## 七、一句话总结

**ColoBot 普通用户版 = 开发者版的安全与深度 + LLM 演示产品的简单与直觉。**

它不是"阉割版"，而是"翻译版"——把架构的优雅翻译成普通人能理解的语言，把隐私的控制权从开发者手里交还给每一个用户。
