# ColoBot 普通用户版规划

> 目标：让不懂编程的人也能拥有一个"会关心你、但永远尊重你"的 AI 伙伴。

---

## 一、现状分析

### 当前 AI 市场分层

| 层级 | 产品 | 用户群 | 特点 |
|------|------|--------|------|
| LLM 演示层 | ChatGPT、Claude、Poe | 普通用户 | 开箱即用，但功能固定，无法定制行为 |
| Agent 框架层 | LangChain、AutoGPT、ColoBot | 开发者 | 高度可定制，但需要编程能力 |
| 中间层 | **缺失** | 想定制但不会编程的用户 | — |

### 普通用户的真实需求

1. **"我想要一个真正懂我的 AI"** — 不是通用助手，是了解我状态、记住我偏好的伙伴
2. **"我想要 AI 主动关心我"** — 不是我问它答，而是它看到我状态不对会主动问
3. **"我担心 AI 会乱说话/泄露隐私"** — 想要控制权，但不想学技术
4. **"我不想部署代码"** — 打开就能用，像用微信一样简单

## 二、产品定位

### 核心差异化

| 维度 | LLM 演示产品 | ColoBot 普通用户版 |
|------|-------------|-------------------|
| 记忆 | 每次对话从头开始 | 长期记忆，越用越懂你 |
| 主动性 | 等你提问 | 主动关心你的状态 |
| 安全感 | "我们保护隐私"（黑盒） | 可查看、可控制、可审计（透明） |
| 定制性 | 选几个预设角色 | 开关式定制行为 |

### 一句话定位

**一个会关心你、记住你、但永远尊重你边界的 AI 伙伴。**

## 三、产品形态

### 3.1 界面设计原则

1. **零概念** — 用户不需要知道 Agent、Tool、Provider、Sentinel
2. **零配置** — 默认值即最优，高级选项折叠
3. **零部署** - Web/App 直接访问，数据本地存储

## 四、技术架构

### 4.1 用户数据存储

**核心原则：数据在用户手里**

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| 纯本地存储 | 隐私最优 | 换设备数据丢失 | 隐私敏感用户 |
| 端到端加密云同步 | 隐私好 + 多设备 | 实现复杂 | 主流方案 |
| 服务端存储 | 简单 | 隐私风险 | 不推荐 |

**推荐方案：端到端加密云同步**

```
用户设备 A                    云端                      用户设备 B
    │                          │                          │
    │  数据 + 用户密钥加密     │                          │
    │ ──────────────────────>  │                          │
    │                          │  存储加密数据             │
    │                          │ <──────────────────────  │
    │                          │                          │
    │                          │  同步加密数据             │
    │ <──────────────────────  │ ──────────────────────>  │
    │                          │                          │
    │  用户密钥解密            │                          │  用户密钥解密
```

用户密钥只存在用户设备上，云端只存加密数据。

**关键设计：LLM 由用户自带**

- 用户输入自己的 OpenAI/Anthropic API Key
- 或使用本地模型（Ollama）
- ColoBot 不经手用户对话内容，只提供架构

## 五、用户旅程

### 5.1 首次使用

```
1. 打开 ColoBot
   ↓
2. 选择：快速开始 / 登录已有账号
   ↓
3. 输入 API Key（或选择本地模型）
   ↓
4. 选择 AI 性格：
   ○ 温暖关心型（默认）— 主动关心，语气温暖
   ○ 高效务实型 — 专注任务，简洁直接
   ○ 平衡型 — 适度关心，不过度
   ↓
5. 选择隐私模式：
   ○ 保守 — AI 只响应你的请求，不主动
   ○ 标准（默认）— AI 会关注状态，适度建议
   ○ 开放 — AI 可以更主动地提供建议
   ↓
6. 开始对话
```

### 5.2 日常使用

```
早上打开 ColoBot
   ↓
AI: "早安！昨晚睡得怎么样？"
   ↓
用户: "还行，就是做梦了"
   ↓
AI 记录睡眠质量，更新用户画像
   ↓
用户: "今天要写完那个报告"
   ↓
AI: "好的，我帮你记下来。预计几点完成？"
   ↓
AI 创建待办，并在设定时间提醒
   ↓
晚上，AI: "报告写完了吗？要不要我帮你检查一下？"
```

### 5.3 心理健康守护触发

```
连续 7 天心情低于 4 分
   ↓
AI 在对话中主动提起:
"我注意到你这周好像不太开心。
要不要聊聊？或者我帮你做点什么？"
   ↓
用户选择：
○ 聊聊
○ 帮我联系好友（v0.5+）
○ 暂时不需要
   ↓
AI 根据选择行动，全程记录在审计日志
```

## 六、商业模式

### 6.1 定价策略

| 版本 | 价格 | 功能 |
|------|------|------|
| 免费版 | ¥0 | 本地存储，基础功能，自带 API Key |
| 个人版 | ¥29/月 | 云同步，多设备，优先支持 |
| 家庭版 | ¥49/月 | 多用户，家庭共享，紧急联系人共享 |

### 6.2 核心原则

1. **用户数据永远属于用户** — 可导出、可删除、可迁移
2. **免费版功能完整** — 不故意阉割核心体验
3. **付费买的是便利** — 云同步、多设备，不是"解锁功能"
4. **API Key 用户自带** — ColoBot 不赚 API 差价

## 七、与开发者版的关系

| 维度 | 开发者版 | 普通用户版 |
|------|---------|-----------|
| 目标用户 | 程序员、技术爱好者 | 普通消费者 |
| 使用方式 | CLI/TUI，自己部署 | Web/App，开箱即用 |
| 定制方式 | 写代码、改配置 | UI 开关 |
| 数据存储 | 自己的数据库 | 本地 + 可选云同步 |
| 核心价值 | 架构可扩展性 | 体验简单好用 |

**技术复用：**

普通用户版复用开发者版的核心包：
- `@colobot/assistant` — 个人助理功能
- `@colobot/sentinel` — 安全守护
- `@colobot/core` — 运行时

只是把 CLI/TUI 换成了 Web/App，把配置文件换成了 UI 设置。

## 九、风险与对策

| 风险 | 对策 |
|------|------|
| 用户不理解"自带 API Key" | 提供详细教程，或提供代购服务（成本价） |
| 数据丢失（本地存储） | 自动备份提示，引导开启云同步 |
| 用户担心隐私 | 完整透明：所有数据可查看、可导出、可删除 |
| 竞品模仿 | 架构优势难以复制：实时评估、Sentinel、渐进自主权 |
| 心理健康责任 | 明确声明：AI 是辅助工具，不能替代专业帮助 |

## 十、总结

ColoBot 普通用户版的核心价值：

1. **让 AI 从"工具"变成"伙伴"** — 记住你、关心你、尊重你
2. **让安全从"承诺"变成"可验证"** — 数据透明、行为可审计
3. **让定制从"编程"变成"开关"** — 不需要懂技术也能定制 AI 行为

这不是把 ColoBot 简化，而是把复杂性藏在界面后面，让普通用户也能享受到架构级的安全与智能。
