# ColoBot 心理健康主动干预功能规划

> 严格遵循"不跳步、不越界、架构原生"的原则，分四个版本逐步释放能力。

## 一、总览

| 版本  | 能力                   | 核心原则                               |
| ----- | ---------------------- | -------------------------------------- |
| v0.4  | 被动建议（无发送）     | 系统只建议，用户全权决定               |
| v0.5  | 用户确认发送           | 系统起草，用户审核后手动发送           |
| v0.6  | 有条件自动发送         | 用户预授权 + 多条件约束 + Sentinel 终审 |
| v0.7+ | 增量优化               | 阈值调优、多级联系人策略、反馈闭环     |

---

## 二、v0.4：被动建议（完全安全基线）

### 触发条件

- 情绪日记连续 N 天（默认 7 天）评分低于用户设定阈值
- 且在此期间，运动、睡眠、社交互动中至少两项同步下降

### 系统行为

- 生成一条干预建议，仅在用户主动发起对话时展示
- **不发送任何邮件，不访问联系人**
- 只在对话中提出建议

### 建议内容示例

```
我注意到你最近一周的情绪指数下降了 30%，睡眠也不太规律。
你之前标记过张某某是你的好友，要不要我帮你起草一封邮件，跟他约个时间聊聊？
```

### 涉及模块

| 模块              | 用途                         |
| ----------------- | ---------------------------- |
| `assistant/life/mood`   | 情绪数据                     |
| `assistant/life/habits` | 习惯与睡眠数据               |
| `assistant/social`      | 读取联系人的"好友"标记（仅名称） |

### 隐私更新

PRIVACY.md 添加：

```
v0.4 起，系统可能在对话中基于你的心理状态提出联系建议，
但不会主动对外发送任何信息。
```

## 三、v0.5：用户确认发送

### 触发条件

同 v0.4

### 系统行为

1. 系统生成干预建议 + 邮件草稿
2. 草稿展示给用户（CLI/TUI/前端），用户可见完整内容
3. **用户确认后，系统调用邮件工具发送**
4. 用户不确认，系统不发送。无自动模式。

### 件草稿规范

| 字段     | 内容                                       |
| -------- | ------------------------------------------ |
| 发件人   | 用户本人的邮箱                             |
| 收件人   | 用户在联系人中标记为"好友"的人             |
| 内容模板 | 见下方                                     |

```
你好，[好友名]。

我是 [用户名] 的 AI 助理。我注意到 [用户名] 最近的状态似乎不太好，
但我不便透露具体细节。如果你方便的话，或许可以主动联系他/她一下。

这封邮件由 AI 自动生成，请勿回复。
```

### Sentinel 介入点

| 介入点       | 职责                                         |
| ------------ | -------------------------------------------- |
| 输出扫描     | 审核邮件草稿，确保不含具体健康数据、财务数据、情绪评分等隐私 |
| 工具白名单   | 件发送工具仅在用户确认后可用                 |

### 隐私更新

- CLI 启动警告增加：`当系统检测到心理健康异常时，会生成建议邮件，需你手动确认后发送`
- `/context` 命令增加显示：`干预模式：手动确认`

## 四、v0.6：有条件自动发送（首次引入系统自主权）

### 前置条件（缺一不可）

1. 用户主动开启"自动干预"开关（**默认关闭**）
2. 用户预设紧急联系人名单（1-3 人）
3. 用户设置自动发送的触发条件（默认：连续 14 天低于阈值）

### 触发条件（全部满足才发送）

| 条件                                         | 默认值           |
| -------------------------------------------- | ---------------- |
| 情绪指数连续超过用户设定天数低于阈值         | 14 天            |
| 期间用户与系统的交互频率降低超过 50%         | -                |
| 联系人列表中"好友"至少有一人有近期互动记录   | -                |
| 在用户设定的时间窗口内                       | 9:00-20:00       |
| 同一联系人 30 天内只发送一次                 | -                |

### 系统行为

1. 自动生成邮件
2. **Sentinel 终审**：安全母 Agent 审核邮件内容，确认无隐私泄露，无越权操作
3. 发送后立即通知用户（系统内通知 + 可选手机推送）
4. 用户可以在发送后撤回（如果邮件服务支持）

### Sentinel 新职责

| 职责         | 内容                                         |
| ------------ | -------------------------------------------- |
| 发送前审计   | 审核邮件内容、收件人、发送时间、是否符合用户预设条件 |
| 发送后审计   | 记录完整日志（何时触发、发送给谁、内容摘要、Sentinel 是否放行） |
| 异常检测     | 短时间内触发多次自动发送时，Sentinel 自动关闭自动干预并通知用户 |

### 隐私更新

- PRIVACY.md 增加"自动干预模式"专章
- CLI 警告改为红色：`警告：自动干预已开启。系统将在检测到严重心理健康异常时自动联系您的紧急联系人`
- `/context` 命令增加显示：当前自动干预状态、最近触发时间、发送历史

## 五、v0.7+：增量优化

### 1. 多级联系人策略

| 严重程度 | 通知对象               |
| -------- | ---------------------- |
| 轻度下降 | 通知密友               |
| 重度下降 | 通知家人或紧急联系人   |

### 2. 反馈闭环

- 发送后一周内，追踪用户情绪指数变化
- 如果情绪改善，标记此联系人为"有效联系人"
- 如果情绪不变或恶化，建议用户更换联系人

### 3. 阈值自适应

- 系统根据用户历史数据，自动调整触发阈值
- 避免对天生情绪波动大的用户频繁误触发

### 4. 非邮件渠道

- 支持短信、飞书、钉钉等渠道（依赖 `@colobot/gateway`）

## 六、架构中不动的部分

无论哪个版本，以下原则不变：

| 原则                   | 说明                                         |
| ---------------------- | -------------------------------------------- |
| 安全母 Agent 永远有最终审核权 | 任何自动发送的行为，Sentinel 在发送前做内容审核，发送后做审计记录 |
| 用户永远有撤销权       | 自动干预开关可以随时关闭，联系人可以随时修改或清空 |
| 数据不出本地           | 联系人信息、情绪数据、邮件内容，全部存储在本地数据库，邮件发送仅调用用户自己的 SMTP |
| 隐私体系同步更新       | 每解锁一个新版本，README、PRIVACY.md、CLI警告、/context 四件套同步更新 |

---

## 七、当前建议

### v0.4 实现时机

v0.4 可以作为 v0.3.x 的一个小功能点先行实现：

- **零风险**：不涉及任何外部通信
- **展示思考深度**：向用户和社区展示 ColoBot 在心理健康领域的思考
- **实现成本极低**：情绪数据查询 + 一条 prompt 模板的调整

### v0.5+ 实现时机

v0.5 及以上，等隐私体系更完善、用户基数更大、社区有足够讨论后再启动。

每一级的解锁都需要经过：

1. 充分的社区讨论
2. 安全审计
3. 隐私文档同步更新

> 你做的不是"多一个功能"，是"多一层系统自主权"。

## 八、技术实现要点

### 数据依赖

```typescript
// 检测触发条件
interface InterventionTrigger {
  moodDays: number           // 连续低情绪天数
  moodThreshold: number      // 用户设定的阈值 (1-10)
  habitsDecline: string[]    // 下降的习惯项 ['sleep', 'exercise', 'social']
  interactionDropRate: number // 用户交互频率下降比例
}
```

### 联系人标记扩展

```typescript
// assistant/social/contact.ts 扩展
interface Contact {
  // 现有字段...
  isCloseFriend?: boolean    // 密友标记
  isEmergencyContact?: boolean // 紧急联系人标记
  lastInteraction?: Date     // 最后互动时间
  interventionCount?: number // 已发送干预次数
  lastIntervention?: Date    // 最后干预时间
}
```

### Sentinel 规则扩展

```typescript
// sentinel/rule-engine.ts 扩展
const interventionRules = {
  // 邮件内容审核
  noHealthData: true,        // 不含健康数据
  noFinancialData: true,     // 不含财务数据
  noMoodScore: true,         // 不含情绪评分
  noSpecificDetails: true,   // 不含具体细节

  // 发送频率限制
  maxPerContactPerMonth: 1,  // 每联系人每月最多 1 次
  maxPerDay: 1,              // 每天最多 1 次

  // 异常检测
  burstDetection: true,      // 突发多次触发检测
  autoDisableOnBurst: true,  // 突发时自动禁用
}
```
